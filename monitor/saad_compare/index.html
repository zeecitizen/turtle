      How MT5 is synced with TradingView (16 Oct 2026, Saad_strategy_1min v1.03 → v1.04)

      Zee: "the only way we can succeed is to sync both mt5 with tradingview. so find a way. i can't miss out on entries i've spent entire day tuning on tradingview"

      Result: on BLUEBERRY:XAUUSD 1 min, 12–15 Oct 2026, 83 of 83 chart trades are the same trade in the MT5 Strategy Tester of Zee's own Blueberry terminal (side and entry minute; 79 also exit in the same minute). Chart +$34,588 vs MT5 +$32,219: the ~$28 a trade gap is real spread and slippage the chart does not charge. Before this work: 63 of 75.

      Read this first: matching the chart is not the same as being profitable. The same settings lost −$53,632 (PF 0.76) on Axi XAUUSD_TK 15 Sep – 15 Oct. The mirror shows the chart's trades faithfully; only MT5 over many weeks, or live fills, can promote a setting (CLAUDE.md).

      2. The architecture (v1.04)

      TradingView Desktop (CDP, BLUEBERRY:XAUUSD, 1 min, Saad indicator)
   │  mainSeries().bars()  via tradingview-mcp CLI  (server.tv_eval)
   ▼
monitor/saad_compare/tv_bars_bridge.py   --export (all history) | --live (append each closed candle, poll 2 s)
   │  writes  %APPDATA%\MetaQuotes\Terminal\Common\Files\tv_bars_XAUUSD.csv
   │          "YYYY.MM.DD HH:MM,open,high,low,close"   (broker SERVER time, closed candles only)
   ▼
mt5/Saad_strategy_1min.mq5  InpBarSource=1  (FILE_COMMON, so the tester agents and the live terminal read the same file)
   candles / EMA / ATR of shift ≥ 1  ← the chart's candles      orders, SL/TP, fills, ticks ← MT5
      • Time: TradingView bar times are UTC epochs. The broker's server time is New York + 7 h: UTC+3 while the US is on summer time (2nd Sunday of March 07:00 UTC to 1st Sunday of November 06:00 UTC), otherwise UTC+2. server_time() does this; no tzdata is needed. PXBT's server is UTC, so this file is for Blueberry and Axi only.
      • Candle layer in the EA: every strategy read goes through BOpen/BHigh/BLow/BClose/BTime(s), Atr(s) and EmaX(fast, s). InpBarSource=1 answers shift ≥ 1 from the arrays tvT/tvO/tvH/tvL/tvC. TvI(s) = g_tvEnd − s + 1, where g_tvEnd is the last chart candle with time ≤ MT5 bar open − 60 s (binary search in TvSync; no look-ahead in the tester, even though the file holds the future). Shift 0 (the forming candle) stays MT5's.
      • Indicators on the chart's candles (TvLoad):
        • EMA: e[i] = e[i−1] + 2/(n+1)·(c − e[i−1]), seeded with the first close; EMA 3/4 converge within minutes.
        • ATR: SMA-14 of the true range, with ta.tr(true) semantics.
        • Live EMA of the forming candle = the chart's emaLive, taken at the MT5 bid.
      • Pacing: OnTick runs the new-candle step (ManageBar, the setup countdown, DetectSetup) only when TvReady(bar) says so:
        • In the tester it is ready at once.
        • Live, it waits up to InpTvWaitSec (20 s) for the chart's candle, re-reading the file at most once a second.
        • If no new chart candle arrives (a minute with no ticks on the chart, or the bridge is down), g_tvStale skips the step: the chart takes no step either, and the EA never re-trades an old candle. The Experts log gets a WARNING when the bridge is down.
        • Warm-up: no setups until the chart has InpEmaSlow·2+19 candles, as in Pine.
      • Robust reads: half-written, repeated or out-of-order lines are skipped. The file is opened FILE_SHARE_READ|FILE_SHARE_WRITE while the bridge appends.

      4. How this page runs a test

      1. 1 · Read TradingView (server.read_tv) reads:
        • the indicator's inputs by position (in_N, names from pine/saad_15min.pine), mapped to EA inputs (DIRECT/CHOICES);
        • the trade export table, by switching exOn on, with the exit reason in the "why" column.
      2. 2 · Run MT5 (server.run_mt5):
        • If InpBarSource is 1, it first calls tv_bars_bridge.export(more=2) to refresh the candle file.
        • "Blueberry demo XAUUSD – your open terminal" (bb_live_run):
          • compiles SaadEMAs.mq5 and the EA into …\Terminal\27280402C90F04230EE7E17540AE21E1;
          • closes C:\Program Files\Blueberry Markets MetaTrader 5 Terminal\terminal64.exe gracefully;
          • runs /config:compare_run.ini (model 4 real ticks, ShutdownTerminal=1, reports\ must exist);
          • reopens the terminal. Zee authorised this on 16 Oct; never copy or read its accounts.dat/servers.dat.
      3. Tester INI: numbers and bools are written k=v||v||0||v||N; strings must be plain k=v (axi_rig.ini_input), or the range text becomes the string's value (the first v1.04 run read "tv_bars_XAUUSD.csv||tv_bars…||N" and traded nothing).
      4. Trades are matched by side and entry minute (±2 min, UTC). Server time = UTC+3 until the US clocks change in November, then UTC+2 (pick it in "Server time").

      5. Re-checking it, trade by trade

      py monitor\saad_compare\why_compare.py 2026.10.11 2026.10.17

      This reads the chart (trades + exit reasons), runs the EA with InpLog/InpVerbose in the Blueberry terminal, and parses the agent log at %APPDATA%\MetaQuotes\Tester\27280402…\Agent-*\logs\*.log (UTF-16; take the text after the last "testing of Experts\Saad_strategy_1min"). It prints one row per trade: TV#n … | MT …, with the empty side meaning unmatched. Output goes to why_out/.

      For each unmatched trade, grep the log at entry minute + 3 h (server time). The EA logs every SETUP, SKIP: <reason>, ENTRY, SL move and EXIT … | reason. To compare feeds, run with InpDumpBars=true and diff saad1m_bars.csv against tv_bars_XAUUSD.csv.

      6. Live use and limits

      • To run live: TradingView open on BLUEBERRY:XAUUSD, 1 minute, with the CDP bridge. Run monitor\saad_compare\start_tv_bars_bridge.bat (--export --live) and keep it open; then attach the EA. Measured: each candle lands ~2 s after its close.
      • Limited history: the chart holds only ~5 days of 1-minute history (6,618 candles on 16 Oct). Long-period courts must pass InpBarSource=0, otherwise there are no candles before the file starts.
      • Data cut-off: the Blueberry tester had no ticks for the current day (16 Oct) at test time.
      • Not mirrored: stop hits and fills inside a minute stay MT5's (real ticks), which is why 4 trades exit in a different minute and P&L is ~$28 a trade lower. That is reality, not a bug.
      • One rare edge: a chart candle MT5 lacks (e.g. 20:59 UTC before the daily break) is folded into MT5's next candle step.
      • 3 · Check sync (sync_check.py, POST /api/sync) re-checks all of the above.
        • Fixes on its own: re-exports the candle file (merge, never shrink), recompiles the EA if Blueberry's .ex5 is older than the code, corrects the page's server time.
        • Reports the rest: wrong symbol or timeframe, chart-only settings, settings changed since the last MT5 run, unmatched trades (each with a reason), and exits in a different minute.
      • After a restart: ensure_up.py --watch starts at logon from Startup\saad_compare_page.vbs (pythonw, no window) and restarts server.py within 20 s if it dies. By hand: py monitor\saad_compare\ensure_up.py --open or start_compare_page.bat. A page served from 127.0.0.1 cannot start its own server, so this is the way.
